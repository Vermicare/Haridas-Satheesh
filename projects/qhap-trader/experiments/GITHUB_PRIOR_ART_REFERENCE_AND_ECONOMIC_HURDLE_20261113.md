**Yes: established open repositories contain reusable engineering methods and research designs that can improve QHAP's reliability and falsification discipline. No project or formula has been shown to guarantee returns.** Prioritize *transaction-cost fidelity*, *execution simulation realism*, and *independent strategy validation* **before adding more AI signals or live brokerage execution**. Reproducing a third-party backtest is not proof the result transfers to the user's **₹10,000 long-only NSE cash-equity account**.

## Two original QHAP formulas — implemented as a pure offline screening tool

[research_economic_hurdle.mjs](../live_readiness/research_economic_hurdle.mjs) is **original, dependency-free code** implementing the following *hypothetical* arithmetic, not a strategy or an order decision:

1. Expected gross round-trip profit, **only if estimated before independent evaluation**: `G = N × expectedFavorableMoveBps / 10,000`, where `N` is expected entry notional.
2. Modeled one-round-trip costs: `C = fixedBrokerageTaxes + N × (2 × oneSideSlippageBps + roundTripSpreadBps + reserveBps) / 10,000`. The 2× applies only to one-side slippage because a round trip has buy and sell. Spread is already round-trip and must **not** be counted twice. If actual measured slippage already includes bid/ask spread, set the standalone spread component to zero to avoid double-counting.
3. Conservative stress screens `G - k × C` for `k ∈ {1,2,3}`. A *hypothetical forecast* passes the **assumed** 3× cost hurdle only when **every** result is strictly positive and input estimates were pre-frozen/independent with externally verified fees. Passing produces `RESEARCH_CLEARS_3X_ASSUMED_FRICTION_ONLY_NO_TRADE`, **never an actual order signal**. A negative or unverified forecast always remains NO_TRADE.
4. For an *already observed* development net loss, the **extra** price-movement profit necessary to reach *arithmetic* break-even without changing any fills is `max(0, -totalNetPnl / roundTrips)`. With user-provided 15bps July results: FAST approximately **₹6.96 additional per completed round-trip**, ONE **₹6.83**, TIME_MOMENTUM_GATE **₹8.54**. These are descriptive gaps, **not price targets, edge estimates or achievable returns**. NO_TRADE has zero trades and no meaningful per-trade hurdle.

These formulas use explicit fixed inputs, not a learning algorithm. Do **not** self-certify model p(win) or a favorable expected move from the same dates. Report losing/null hypotheses and consider whether no-trade is the rational answer.

### Why optimizing indicator thresholds will not solve the immediate problem

From the 84-day actual-provider-data development aggregate at **15bps/side**, FAST's gross price movement was **−₹68.15 before a further ₹3,431.82 modeled combined fees and slippage**; ONE's gross total **+₹1.98 across 84 round-trips** versus ₹575.90 modeled friction. Slight parameter changes or a more complex AI component do not create a demonstrated positive pre-cost signal. If the process cannot forecast enough economically executable movement to beat realistic total friction, **abstention beats activity**.

## Implementation ordering (one independently reviewed capability at a time)

**Stage A — economic/execution integrity**: implement a separately versioned **cash-equity-specific Upstox dated fee model**, test against independently obtained official charge schedule/contract notes where user is entitled, include intraday vs delivery product, and retest same *development* dates without retuning trading rules. Reject optimistic intraminute target execution; model limit order, uncertainty, gap and partial fill as loss/unknown; do not guess actual bid/ask depth without authorized feed.

**Stage B — new hypothesis research**: consider precommitted, less turnover-intensive ideas such as daily/weekly relative momentum or volatility-conditioned trend as **unverified alternatives**, with explicit cost/overnight-gap tests and ₹10,000 cash-only feasibility. No claim they win; avoid leveraging derivatives or auto-placing real orders. Record new code SHA, labels and parameters **before opening any new evaluation period**; quarantine current 89 development days.

**Stage C — independent model selection**: split new authorized multi-year data by time and genuine regimes, use purging and embargo for overlapping forward-return labels, point-in-time stock universes/corporate actions, compare to NO_TRADE and a simple baseline, account for multiple hypotheses. Pre-register at least **60 untouched distinct exchange dates across 3 independently characterized regimes** and preserve separate chronological forward paper observations. If actual net modeled edge is still negative, reject. Do not repeatedly re-use the same untouched holdout after observing results.

**Stage D — broker execution later**: Upstox user sandbox fake order **place, modify, cancel ACKs** are already authenticated and tested locally; however the sandbox doesn't independently certify final order status/fills. Only after independently positive after-cost evidence and explicit live-order user authorization may the separate broker/compliance review proceed. **The current QHAP code intentionally has NO real order route.**

## Audit controls

- Source data local/private; never upload raw authorized Upstox candles, tokens or identifiers to public GitHub or this assistant.
- Users report verbal Upstox approval for **historical backtesting/read-only live-feed hypothetical paper**; this is user-attested, not verified written exchange permission, and **does not authorize live execution**.
- Respect QHAP project-specific user instruction: **do not send/reply/forward/resend emails without approval of the specific message/recipients**; other project's established outreach workflows remain unaffected.
- CI tests are synthetic/offline and must **not** be misrepresented as actual market performance.
