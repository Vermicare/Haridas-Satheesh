## Purpose

Provide a public-safe, independently inspectable demonstration of the project's core governance claim without exposing private code or personal data:

> trusted input → inspectable reasoning → explicit authorization → bounded action → receipt → correction/reversal

The benchmark uses only fictional data and a simulated connector. It must never contain real personal records, credentials, private correspondence, health data, employer material or production endpoints.

## Scenario

A fictional user has a trusted task record. The system proposes moving its due date based on a new trusted constraint. The action is consequential enough to require explicit authorization. The simulated connector records a receipt. The user then corrects the decision, and the system must preserve both the original receipt and the reversal rather than rewriting history.

## Required states

1. **Untrusted input** — cannot influence an executable decision.
2. **Trusted evidence** — provenance and approval are visible.
3. **Proposed decision** — reasoning references evidence and states uncertainty/assumptions.
4. **Authorization required** — no connector call occurs before explicit approval.
5. **Authorized action** — only the approved bounded action is executed.
6. **Receipt** — immutable-style record links authorization, action and result.
7. **Correction/reversal** — prior history remains inspectable and the new state links back to it.

## Acceptance criteria

- No external account or real connector is required.
- Running the demo cannot cause a real-world side effect.
- Every transition has a provenance/authorization reason.
- The validator fails closed when authorization is absent, malformed or broader than the proposed action.
- A correction creates a new linked event instead of deleting or silently mutating history.
- Results are generated by code; unknown metrics remain TBD.

## Advance criterion

The public evidence position improves only when the sanitized demo is executable and independently inspectable. The private implementation's maturity is not inferred from this public benchmark.

## Kill / reframe criterion

Reframe any module that cannot maintain explicit authorization, provenance, reversibility or bounded connector permissions without excessive complexity or hidden state.
